# neca 检查方案（v1.0 RC 稳定化）

> 目标：在 v1.0.0 前用分层、可复现的检查降低回归与发布风险。
> 原则：优先发现安全边界、数据损坏和用户可见回归；生产只做只读或明确批准的有回滚演练。

## 1. 分级

- **P0**：认证绕过、CSRF、helper 越权、私钥/会话泄露、数据丢失、错误配置导致写模式失控。
- **P1**：命令/路由不可用、语言切换失效、签发/吊销/回收站/设置保存/只读切换失败、升级回滚失败。
- **P2**：布局、文案、提示、非关键样式、帮助缺项。

## 2. 自动化门禁

每次提交/候选前：

1. gofmt、go vet。
2. `go test -race ./...`。
3. CLI/Web locale key 对齐。
4. `check-docs`、`check-ascii`。
5. `make shadow`（旧实现功能影子对比）。
6. CI 全绿；amd64/arm64 构建。
7. 新增/修改路径必须有关闭或回退测试。

## 3. CLI 检查矩阵

- 所有 namespace：`cert`、`pki`、`trash`、`web`、`config`、`wizard`、`doctor`。
- 所有命令/子命令的 `--help` 退出 0、无配置依赖、语言正确。
- `--lang en-US/zh-CN` 切换：菜单、帮助、错误、成功输出。
- 读写命令：参数校验、dry-run、Y/N 默认 N、`--yes` 审计、JSON 信封。
- 危险操作：lock、lockdown、trash purge、web readonly；只操作明确命名服务。
- 使用临时 PKI/配置执行写入类测试；生产只做只读 smoke。

## 4. Web 检查矩阵

隔离环境 + 临时密码，生产不跑破坏性测试：

- 登录、退出、会话过期。
- 侧栏二级菜单展开/高亮。
- 主题/语言下拉框与刷新持久性。
- 签发页：平台勾选、脚本勾选、导航高亮、输入校验。
- 设置页：安全表单、保存对话框、密码/确认、未保存提醒。
- readOnly 从否改是：保存成功、表单移除、回退值显示、刷新保持。
- 只读后不可由 Web 恢复写模式；后台恢复。
- 关于页、顶部下载按钮移除。
- 响应式布局与无 JavaScript 降级提示。

## 5. 集成与安全

- helper 白名单、只读/可写状态、socket 权限、配置写回。
- 高风险保存路径必须进入 handler，不得被 readOnlyGuard 提前拦截。
- 配置/PKI/web-secrets 权限与原子写入。
- 审计日志轮转、Web 审计、失败路径。
- 备份→升级→回滚演练；strongSwan 不受 Web 操作影响。
- 依赖、供应链、Secret 扫描。

## 6. 发布检查

- 版本/tag/Release/GHCR 一致。
- v0.4.1 → 候选升级与回滚演练。
- 1 周观察；只接受修复、文档和安全补丁。
- 生产部署需单独确认；保留回滚镜像与配置/PKI 备份。
- 失败即回滚，记录根因与回归用例。

## 7. 缺陷处理

- P0：停止发布，立即修复并补回归测试。
- P1：阻塞 v1.0.0；修复后重跑相关矩阵。
- P2：可进入已知问题清单，但不隐藏安全影响。
- 每个修复必须有：根因、影响面、回归测试、发布说明。

## 8. 需要用户决定

1. **CLI 语言/子命令 help 修复是否提交**
   - 推荐：提交为一次独立修复，发布 RC.8 后部署；不要与下一步功能混在一起。
2. **RC.8 是否在生产部署**
   - 推荐：先在隔离环境跑完 CLI/Web 矩阵，再部署 RC.8；保留 RC.7 回滚镜像。
3. **v1.0.0 时间**
   - 推荐：观察期到 2026-11-23，RC.8 部署后至少再观察数日；无 P0/P1 才发布 v1.0.0。
4. **高风险设置/写模式是否保持开启**
   - 推荐：若近期仍需 Web 写操作则保持；不操作期间可恢复只读，降低攻击面。
5. **历史 legacy 文档归档位置**
   - 推荐：保留在 `docs/development/` 作为历史参考；不删除历史。
6. **破坏性测试范围**
   - 推荐：只在隔离测试环境执行 issue/revoke/trash/purge 全流程；生产只读 smoke。
7. **文档目录结构**
   - 推荐：保持 `docs/development/`、`docs/evaluations/`、docs 根 `MILESTONES.md`；历史 legacy 放 development，不删除历史。
8. **提交拆分**
   - 推荐：CLI 语言/help 修复与 docs 重组分开提交；docs 重组已验证链接，但仍不应夹带行为变更。

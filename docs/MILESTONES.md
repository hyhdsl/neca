# neca 开发目标与里程碑

> 更新：2026-11-16 · 当前基线：v0.4.1（tag 6060c2b）
> 本文件是里程碑与开发优先级的权威来源；历史实施细节见 [neca-development.md](neca-development.md)，当前开发入口见 [DEVELOPMENT.md](DEVELOPMENT.md)。

## 1. 当前状态

- M0–M8 已完成；v0.4.1 已发布并部署，Web 默认只读。
- CLI、只读 Web、受控 root helper、配置目录挂载、SIGHUP、helper 幂等缓存均已落地。
- 帮助站：根主页（中英切换）、中文 /zh/、英文 /en/、sitemap。
- 当前 main：4dc5f2e；生产环境仍建议只通过 OpenSSH 本地转发访问 Web。
- 当前定位：单租户、CLI 优先、默认只读、可审计的小型/中型 strongSwan 证书管理。

## 2. 重新确定开发目标

产品目标：在小规模 strongSwan IKEv2 部署中，以最小攻击面和可恢复的方式管理证书；破坏性操作默认由后台 root 控制，Web 只承担查看与受限操作。

工程目标：

1. 安全默认：只读、无公网默认暴露、敏感配置不经 Web 修改。
2. 可恢复：任何删除/停止/回滚操作都有后台确认、审计与恢复路径。
3. 可维护：新功能能按模块增加或移除，不把 Web、helper 和 core 耦合成不可拆的整体。
4. 文档收敛：里程碑、当前开发指南、历史设计分离；中文为主版本。

暂不追求：多租户 SaaS、复杂高可用、无人值守自动签发、默认公网 Web、OpenAPI 对外契约。

## 4. 新里程碑

### M9：安全与可恢复性（当前主线）

- M9.1 Web 导出后台开关（默认关闭、审计、UI/API 同步）。
- M9.2 后台紧急断开：只允许 SSH/root CLI，明确“停止容器”与“会话失效”的区别。
- M9.3 备份/恢复与回滚演练：PKI、config、web-secrets、clients、meta、downloads。
- 出口：任何紧急操作可在后台执行并可审计；恢复演练通过；不改变默认只读边界。

### M10：受控 Web 管理

- Web 设置页：安全偏好 + 只读展示安全配置；不提供 readOnly/adminCNs/passkey 修改。
- 证书删除回收站：后台确认、隔离区、恢复、过期清理；Web 不物理删除。
- 出口：删除/恢复/清理流程有测试；私钥访问与保留期明确。

### M11：可维护性与可观测性

- Web 路由/功能模块拆分；feature flag；CLI 子命令增删保持低成本。
- 健康状态、日志/审计保留与轮转；发布/回滚检查清单。
- 出口：新增一个试点功能只需新增模块/路由/测试；不改变外部行为。

### M12：公网访问安全（后置）

- TLS + mTLS 或 Tunnel/Access；默认仍 OpenSSH。
- 需单独威胁建模、证书生命周期和访问审计。

### M13：API 稳定化 / OpenAPI（按需）

- 仅在外部自动化需求明确后启动；当前 API 继续标记实验性。

## 5. 安全与未考虑事项

- 紧急操作的二义性：停止 Web 不等于吊销 VPN 会话；必须分开描述，避免误以为能断开 IKEv2。
- 会话撤销：当前会话是签名 Cookie + 内存撤销表；重启会丢失撤销表。若要“所有会话立即失效”，需要会话代际/密钥轮换，且要考虑 Web 单文件挂载与重启。
- 回收站不是安全删除：SSD、快照、备份可能保留私钥；UI 不得承诺“彻底删除”，只能承诺隔离与后续清理。
- 索引一致性：删除/恢复期间必须锁住写操作；回收站清单要能防止半完成状态。
- 设置页权限：Web 账号一旦能改安全设置，就绕过了 root helper 边界；必须后台-only。
- 导出开关：默认关闭；即使开启，也要审计、限速、避免把 API 变成批量枚举接口。
- 命名/品牌：删除字母 n 只是降低视觉商标风险；正式名称不声称注册，外部使用建议注明项目链接。
- 文档权威：中文 README/帮助为主版本；英文 README/帮助可能滞后，不作为最终依据。
- 测试与回滚：每个新功能都要有“关闭/回退”路径，尤其是删除和紧急停止。

## 6. 需要用户决策

1. 紧急断开：目标是“停止 Web+helper 容器”（最快、会中断服务），还是“只读 + 使所有 Web 会话失效”（保留只读服务），还是两者都提供？是否需要一条命令？
2. 回收站：Web 是否只提交“删除请求”，物理确认只能在后台？保留期（7/30 天）？恢复是否允许已吊销证书复活？清理是否需要二次确认？
3. 设置菜单：只放语言/显示等安全偏好，还是也允许修改 idleTimeout？安全配置是否永远只读展示？
4. 导出开关：默认关闭是否确认？开关放在 neca web export on/off 还是 neca config？允许导出 CSV、还是只允许单个证书下载？
5. 源代码优化：接受“增量抽取路由/feature flag”，还是希望做一次较大重构？是否允许为可维护性暂缓新功能？
6. 里程碑顺序：是否接受 M9 先做“导出开关 + 紧急断开 + 备份恢复”，再进入 M10 回收站/设置？
7. OpenAPI：确认继续暂缓（本轮建议：是）。
8. 命名：正式名称首次出现使用 “Neko's Efficient Certificate Administrator（neca）”，正式简写用 NECA；是否确认？

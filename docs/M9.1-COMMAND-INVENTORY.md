## 7. 目标命令树

### backend CLI

- <code>neca cert list|verify|issue|reissue|revoke|unrevoke|trash|export|platform|package</code>
- <code>neca pki index sync</code>
- <code>neca pki downloads list|clean</code>

- <code>neca config init|show|validate|export-env|path</code>
- <code>neca web status|readonly|idle-timeout|hash-password|lock|lockdown|export</code>
- <code>neca version|help|wizard</code>

### Web

- 只读：dashboard、certs、downloads、exports（开关开启时）
- 写：issue/revoke/unrevoke/reissue、trash move、低风险偏好、高风险设置（仅后台开关开启）
- 不提供：物理 purge、lock/lockdown、配置/密钥编辑、任意 shell

### helper

- 结构化操作注册表，不接受命令字符串
- 每次请求记录 origin / actor / requestId
- 新增 <code>trash</code> 与受限 <code>settings-update</code> 时才扩展白名单

## 9. 确认策略清单

| 操作 | Y/N | <code>--yes</code> | 备注 |
|---|---|---|---|
| <code>web lock</code> | 是（默认 N） | 允许，审计 | 只读 + sessionEpoch |
| <code>web lockdown</code> | 是（默认 N） | 允许，审计 | 只停明确服务 |
| <code>trash purge</code> | 是（默认 N） | 允许，审计 | 不再输入 CN |
| 高风险设置 | 是（默认 N） | 后台允许；Web 仍 UI 确认 | 重新认证/CSRF/审计 |
| <code>cert trash</code> | 建议否 | — | 可恢复；仍审计 |
| <code>cert revoke/unrevoke/reissue</code> | 建议保持现有 dry-run/审计，不强制 Y/N | — | 需用户确认是否要统一 |
| <code>cert issue</code> | 建议否 | — | 常规操作；dry-run/审计 |

非交互环境下未传 <code>--yes</code> 且需要确认时：**默认 N、退出**，不得静默继续。

确认逻辑必须独立成函数/接口，便于后续按功能增删 Y/N：

~~~go
type ConfirmRequest struct {
    Action  string
    Subject string
    Default bool // false
}
type Confirmer interface {
    Confirm(ctx context.Context, req ConfirmRequest) (bool, error)
}
~~~

- 后台 CLI 使用 TTY Y/N 实现；<code>--yes</code> 在该函数外显式跳过并写入审计。
- Web 高风险设置使用 UI Y/N；不能复用 CLI 的 TTY 实现。
- 没有确认需求的功能直接不注入 Confirmer，不写空壳确认。
